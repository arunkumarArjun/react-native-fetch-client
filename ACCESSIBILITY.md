# Accessibility Statement

We are committed to ensuring digital accessibility for everyone who uses, contributes to, or reads the documentation for **react-native-fetch-client**.

## Standards & Principles

We aim to adhere to the [Web Content Accessibility Guidelines (WCAG) 2.1 Level AA](https://www.w3.org/WAI/standards-guidelines/wcag/) across all developer documentation, websites, and demo applications:

- **Perceivable**: All text content provides sufficient color contrast. Code snippets, diagrams, and illustrations include text equivalents and clear syntax formatting.
- **Operable**: Documentation pages and web applications are fully navigable using a keyboard alone, without requiring mouse interactions or hover traps. Interactive elements have clearly defined `:focus-visible` outlines.
- **Understandable**: Clear terminology, structured document hierarchy, predictable navigation, and comprehensive TypeScript error explanations.
- **Robust**: Clean semantic HTML in our web documentation to ensure compatibility with screen readers (VoiceOver, NVDA, JAWS, TalkBack).

## Developer Experience (DX) Accessibility

While `react-native-fetch-client` is primarily a headless HTTP client, we prioritize developer accessibility:
- **Descriptive Error Codes & Messages**: Errors provide clear, actionable explanations and debug information rather than cryptic numbers.
- **Accessible Demos**: Mobile and web example applications demonstrate accessible patterns, including screen reader labels and appropriate contrast.

## Reporting Accessibility Issues

If you encounter accessibility barriers when using our documentation, website, or repository:

1. **Open an Issue**: File a GitHub Issue using the [Bug Report](https://github.com/arunkumarArjun/react-native-fetch-client/issues/new?template=bug_report.yml) template and prefix the title with `[a11y]`.
2. **Details to Include**:
   - The URL or file where the barrier was found.
   - The assistive technology used (e.g., screen reader version, browser, OS).
   - A brief description of the issue and the expected accessible behavior.

We take accessibility feedback seriously and aim to address reported issues promptly.
